# Spacebar Login Troubleshooting Reference

Covers the most common reasons a user exists in the DB but login returns
**50035 "Invalid Form Body" / "Invalid login or password"**.

## 1. Duplicate Usernames (Most Common)

Spacebar's `User.findOneOrFail()` with `where: [{phone}, {email}, {username}]`
returns **any** matching user. If multiple accounts share the same username
(from repeated registrations or DB restoration), TypeORM may return the wrong
one — an older user with a different (or missing) password hash.

### Symptom

- Registration returns a token (user created).
- Subsequent login with that password fails with `INVALID_LOGIN`.
- DB shows multiple rows for the same username.

### Fix

```sql
-- Keep only the MOST RECENTLY CREATED user, delete older duplicates
DELETE FROM users
WHERE username = 'target-user'
  AND id != (
    SELECT id FROM users
    WHERE username = 'target-user'
    ORDER BY created_at DESC LIMIT 1
  );

-- Also clean up orphaned member records
DELETE FROM members WHERE id IN ( ...deleted-user-ids... );
```

Verify login works after cleanup.

## 2. Python vs Node.js bcrypt Incompatibility

Python's `bcrypt` library generates `$2b$` hashes that **Node.js `bcrypt`
cannot verify**, even though `bcrypt.checkpw()` returns True in Python.

### Root Cause

The Python bcrypt library (v5.x) and Node.js `bcrypt` (v5.x) use different
internal salt representations. A hash generated by one is rejected by the
other despite identical prefixes.

### Fix — Use Node.js to generate the hash

```bash
cd /opt/spacebar
HASH=$(node -e "const b=require('bcrypt'); console.log(b.hashSync('password', 10));")
psql -h 127.0.0.1 -U hamilton -d spacebar \
  -c "UPDATE users SET data = jsonb_set(COALESCE(data, '{}'::jsonb), '{hash}', '\"$HASH\"') WHERE id = 'user-id';"
```

### Verification

Always verify with Node.js bcrypt, not Python:

```bash
node -e "const b=require('bcrypt'); console.log(b.compareSync('password', '\$2b\$10\$...'));"
# Must print: true
```

## 3. PostgreSQL Password Mismatch After DB Restore

When restoring a `pg_dump` to a new PostgreSQL cluster (or after re-creating
the role), the password stored in the cluster's authentication system may
desync from what Spacebar's connection string uses.

### Symptom

- `psql -h 127.0.0.1 -U hamilton -d spacebar` fails with auth error.
- `sudo -u postgres psql -d spacebar` works.
- Spacebar logs show `Error: listen EADDRINUSE` on startup (crashed
  processes pile up).

### Fix

```bash
sudo -u postgres psql -c "ALTER USER hamilton WITH PASSWORD 'the-password-from-env';"
```

Then kill ALL stale Spacebar processes and restart:

```bash
fuser -k 3100/tcp  2>/dev/null   # force-kill everything on the port
sleep 3
# verify port is clear
ss -tlnp | grep 3100 || echo "Free"
# restart with correct connection string
```

## 4. Gateway State File Bleed

After unclean gateway termination (`taskkill /F`, `process(kill)`), stale
state files in the profile directory can cause the next gateway instance to
use old cached tokens.

### Symptom

Gateway log shows `login id=OLD_USER_ID` even though the `.env` file was
updated with a new token.

### Fix — Clear stale state files

```bash
rm -f ~/AppData/Local/hermes/profiles/<profile>/gateway.pid
rm -f ~/AppData/Local/hermes/profiles/<profile>/gateway_state.json
rm -f ~/AppData/Local/hermes/profiles/<profile>/gateway.lock.spacebar
rm -f ~/AppData/Local/hermes/profiles/<profile>/.gateway_state*
```

## 5. Env-var Bleed Between Terminal Calls

The Hermes terminal tool preserves shell environment across calls. If you
previously ran `set -a; source .env; set +a`, the `DISCORD_BOT_TOKEN` env
var persists in the shell. Background gateway processes inherit this stale
value even after you update the `.env` file.

### Fix

Use a Python launch script that builds a clean `env` dict (see
`scripts/start-fleet.py` in the skill directory), or explicitly unset the
stale vars in the same command that starts the gateway:

```bash
unset DISCORD_BOT_TOKEN SPACEBAR_BOT_TOKEN SPACEBAR_GATEWAY_URL SPACEBAR_API_URL
export HERMES_HOME_BASE="${HERMES_HOME}"
source "${HERMES_HOME}/profiles/<profile>/.env"
python scripts/spacebar-gateway.py <profile>
```

## 6. Fermi instances.json Cache

Fermi loads `instances.json` **exactly once at process startup**. Editing the
file on disk without restarting the Fermi node process has **zero effect** on
the running server.

### Fix

```bash
kill $(pgrep -f 'node dist/index') 2>/dev/null
sleep 1
cd /opt/fermi && nohup node dist/index.js >> /opt/fermi/fermi.log 2>&1 &
```

Verify immediately after restart:

```bash
curl -s http://localhost:8081/instances.json | head -5
```

## 7. Fermi Service Worker Cache

Fermi registers a service worker that caches ALL static files. This cache
persists across hard refreshes and domain migrations.

### Fix — Programmatic cache clear

The service worker listens for a `ForceClear` message:

```js
navigator.serviceWorker.controller.postMessage({ code: "ForceClear" });
```

Or in DevTools: Application → Storage → Clear site data.
