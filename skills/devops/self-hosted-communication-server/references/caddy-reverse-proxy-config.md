## Caddy Reverse Proxy Configuration

If the Spacebar server runs behind Caddy (as at discy.your-domain.example), the CDN routes MUST be explicitly proxied to the Spacebar backend.

### Domain-Specific Icon Routing: gc vs discy

The two domains serve different icon sets. DO NOT apply the same `/icons/*` rule to both:

- **`discy.your-domain.example`** (API server) — `/icons/*` must proxy to the Spacebar API (port 3100), because Discord API endpoints like guild/emoji icons live there.
- **`gc.your-domain.example`** (Fermi client) — `/icons/*` must fall through to the Fermi client (port 8081), because these are UI `.svg` files at `dist/webpage/icons/`. If proxied to the API server, every icon 404s.

**Fix for gc.your-domain.example:** Remove the `@icons` matcher entirely so the default handler serves them:

```caddy
# ✅ RIGHT — icons fall through to Fermi client
gc.your-domain.example {
    @assets path /avatars/* /files/* /cdn/* /app-assets/* /app-icons/* ...
    handle @assets { reverse_proxy 172.17.0.1:3100 }
    handle { reverse_proxy 172.17.0.1:8081 }    # ← /icons/* lands here
}
```

**Fix for discy.your-domain.example:** Keep `/icons/*` in the CDN matcher:

```caddy
# ✅ RIGHT — API icons proxy to Spacebar server
discy.your-domain.example {
    @assets path /avatars/* /icons/* /files/* /cdn/* ...
    handle @assets { reverse_proxy 172.17.0.1:3100 }
    handle { reverse_proxy 172.17.0.1:8081 }
}
```

### VPS Caddy Bind Mount — Editing the Config

On the the operator VPS, the Caddy config is a **bind mount** from the host filesystem. Commands like `docker cp` and `docker exec cat > ...` fail because the bind mount keeps the file busy in the container:

```
/home/ubuntu/Caddyfile (host, owned by root)  →  /etc/caddy/Caddyfile (container bind mount)
```

To update: edit the host file with `sudo`, then restart the container:

```bash
sudo tee /home/ubuntu/Caddyfile > /dev/null << 'ENDCONFIG'
# ... new config ...
ENDCONFIG
docker restart hmac-caddy
```

This is the ONLY reliable way to change the Caddy config for this deployment. Any other method (docker cp, docker exec cat >, caddy reload from inside) silently fails or uses stale config.

### Critical: CDN Routes Must Target Spacebar, NOT the Web Client

The CDN module (avatars, attachments, emojis, banners, etc.) runs inside the same Spacebar Express app on port 3100, NOT on the web client port (8081). If CDN paths fall through to the default handler (the web client), they return HTML instead of actual CDN content.

#### ⚠️ Caddyfile sed trap — replacing one port breaks all routes

When changing a single route's target port in the Caddyfile (e.g., moving `/avatars/*` from 3100 → 3456), NEVER use a catch-all sed replace:

```bash
# ❌ WRONG — replaces ALL 3100→3456, breaking API, WS, files, CDN
sed -i 's|reverse_proxy 172.17.0.1:3100|reverse_proxy 172.17.0.1:3456|g' Caddyfile
```

Instead, rewrite the full Caddyfile with `sudo tee` + heredoc, or use a highly specific sed pattern targeting only the avatar block. After a bad replace: restore the Caddyfile with correct assignments (API/WS/files/CDN → 3100, avatars → 3456) and `docker restart hmac-caddy`.

### Domain Consolidation (discy → gc redirect)

When migrating from one domain to another (e.g. `discy.your-domain.example` → `gc.your-domain.example`):

1. **Caddy redirect**: Add a `redir` block for the old domain that issues a 301 permanent redirect to the new domain, preserving the URI:

```caddy
# Old domain — permanent redirect to new domain
discy.your-domain.example {
    redir https://gc.your-domain.example{uri} 301
}
```

2. **Spacebar config**: Update ALL references in `config.production.json`:
   - `general.serverName`
   - Gateway endpoints (wss://)
   - CDN endpoints
   - API endpoints
   - Instance image URL

3. **Restart both services**: `sudo systemctl restart spacebar.service` + `docker exec <caddy> caddy reload`

4. **Verify**:
   - Old domain: `curl -sI https://discy.example.com/` → `301 Moved Permanently → https://gc.example.com/`
   - New domain: `curl -s https://gc.example.com/api/v9/gateway` → `{"url":"wss://gc.example.com/"}`
   - Old domain API calls redirect: `curl -sL https://discy.example.com/api/v9/ping` → `{"ping":"pong!"}` (followed redirect)

5. **Client cache**: Users may need a hard refresh (Ctrl+Shift+R) to clear cached application data that still references the old domain for asset URLs (avatars, banners). These URLs are generated by Spacebar at request time using the configured CDN endpoint — once the config is updated and server restarted, fresh API responses will use the new domain.



**Symptom:**
- File uploads via `POST /channels/{id}/messages` with a `file` form field return `curl status 000` (connection reset) or `400` with `SyntaxError: Unexpected token '<'` — because Spacebar's multer receives the web client's HTML page instead of the multipart form data
- CDN resource paths like `/avatars/*` or `/attachments/*` return `Content-Type: text/html` instead of JSON or image data

**Fix:** Add a `@cdn` path matcher BEFORE the default catch-all handler:

```caddy
discy.example.com {
    encode gzip
    @spacebar_well_known path /.well-known/spacebar /.well-known/spacebar/client /.well-known/spacebar-v2
    handle @spacebar_well_known {
        reverse_proxy localhost:3100
    }
    @api path /api/*
    handle @api {
        reverse_proxy localhost:3100
    }
    @cdn path /attachments/* /avatars/* /banners/* /emojis/* /channel-icons/* /role-icons/* /splashes/* /team-icons/* /app-icons/* /badge-icons/* /embed/*
    handle @cdn {
        reverse_proxy localhost:3100
    }
    @ws {
        header Upgrade websocket
    }
    handle @ws {
        reverse_proxy localhost:3100
    }

**⚠️ Do NOT use `header Connection *Upgrade*`** — The Connection header value varies between clients. Some send `Connection: Upgrade`, others send `Connection: keep-alive, Upgrade`. Caddy's glob matching has edge cases with multi-value Connection headers, causing WebSocket upgrade requests to fall through to the wrong handler. The `Upgrade: websocket` header is the **defining** marker — present on every WS request regardless of client library.
    # Everything else → web client on port 8081
    handle {
        reverse_proxy localhost:8081
    }
}
```

The `@cdn` path list must cover ALL routes registered by the CDN module. Missing any will silently serve the web client's HTML instead.

### Apply and Verify

```bash
# Write config into Caddy container:
docker exec -i <caddy-container> tee /etc/caddy/Caddyfile > /dev/null
# Reload:
docker exec <caddy-container> caddy reload --config /etc/caddy/Caddyfile

# Verify:
curl -sk -o /dev/null -w "%{http_code}" https://discy.example.com/avatars/test.png
# → 200 or 404, NOT text/html
curl -sk -D - https://discy.example.com/avatars/test.png 2>&1 | grep -i content-type
# → Should NOT be text/html
```
