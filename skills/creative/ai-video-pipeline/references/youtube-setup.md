# YouTube API Setup — Iterative Review Workflow

Full setup steps at `docs/youtube-setup.md` in the yt-animations project root. This reference covers the key patterns.

## OAuth Setup
- Create Google Cloud Project → Enable YouTube Data API v3 → OAuth consent screen (External) → Create Desktop OAuth client ID → download `client_secret.json`
- **Port conflict**: Docker uses 8080. Use `port=8081` in `run_local_server()`.
- **Wrong account**: Delete `token.pickle` and re-run OAuth with the correct Google account.
- **Test user**: Add your email to OAuth consent screen test users before authorizing, or Google blocks with "access_denied".

## Iterative Review Cycle (User's Preferred Workflow)
1. Agent uploads video as **unlisted** via `python scripts/youtube_manager.py upload video.mp4 --title "Title" --privacy unlisted`
2. User reviews on phone (YouTube app) via the autogenerated `youtu.be/<id>` link
3. If no good → user says "delete it" → agent runs `python scripts/youtube_manager.py delete <video_id>`
4. Agent rebuilds with requested changes
5. Re-upload as unlisted → user reviews → repeat until good
6. Finalize: change privacy to public or re-upload as public

## Commands
```bash
# Upload
python scripts/youtube_manager.py upload "path/to/video.mp4" --title "Title" --description "Desc" --privacy unlisted

# List recent
python scripts/youtube_manager.py list

# Delete
python scripts/youtube_manager.py delete <VIDEO_ID>

# Get URL
python scripts/youtube_manager.py url <VIDEO_ID>
```

## Troubleshooting
| Problem | Fix |
|---------|-----|
| `OSError: port in use` | Docker uses 8080. Use port 8081. |
| `token.pickle` wrong account | Delete token.pickle, re-run OAuth. |
| `access_denied` | Add your email as Test User in OAuth consent screen. |
| `quotaExceeded` | Free tier: 10,000 units/day (~100 uploads). Wait or upgrade. |
